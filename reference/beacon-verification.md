# ＋Beacon ボタン（PB-BTN-01）実機検証記録（2026-09-26）

LIFELiNK の物理ボタン経路（iBeacon）を Samsung Galaxy（SM-S942Z / Android 16 / API 36、USB 充電中）で検証した結果の要約。詳細な経緯と決定は `doc/plan.md` 6b 章、タスクは `doc/tasks.md`（P0-14a / P0-15 / P3-02〜P3-04）を正とする。

## 1. ボタン側の仕様と設定

- 仕様書: `doc/reference/＋Beacon ボタン_製品仕様書.pdf`（Braveridge、Version 1.0.0）。IDLE（電波停止）で出荷され、NFC で RUNNING にして初めて広告する。電池の抜き差しでは状態が変わらない。電池低下は Major 最上位 bit で通知。
- メーカーアプリ `com.braveridge.pbeacon_button` の「NFC で設定確認・変更」で読み書きする。
- 採用設定: **ボタン検知モード / アドバタイズ間隔 1 秒 / アドバタイズ送信時間 60 秒 / TxPower 0 dBm**。送信時間は `連続発信 / 10 秒 / 60 秒 / 3600 秒` から選べる。
- デバイス ID `49C6FC80585C0E3A`、FW 1.0.5。

## 2. 広告と操作の対応（実測で確定）

| 操作 | スロット | UUID | Major（生値） | Minor |
| --- | --- | --- | --- | --- |
| 待機（操作なし、常時） | Beacon0 | `BB192440-9E4F-497D-8ACE-7B2BA67CC2FE` | 11665 | 31295 |
| ボタン1 短押し | Beacon1 | `581E31D6-E7BA-407A-B12E-949ACE475485` | 7290 | 36652 |
| ボタン1 長押し | Beacon1 | 同上 | 23674（7290 + `0x4000`） | 36652 |
| ボタン2 短押し | Beacon2 | `AA82CE42-BFC7-4182-B760-1CCA10116876` | 12975 | 16823 |
| ボタン2 長押し | Beacon2 | 同上 | 29359（12975 + `0x4000`） | 16823 |

- Major の bit15（`0x8000`）= 電池低下、bit14（`0x4000`）= 長押し、下位 14 bit = 設定値。
- 押下すると対応スロットを送信時間だけ送り、その後 Beacon0（待機）に戻る。送信中の再押下は送信時間を延長する。
- 広告パケット数はボタン押下回数ではない。iBeacon に押下カウンタは無く、**送信中に同じボタン・同じ押し方で押し直しても広告上は区別できない**。

## 3. LIFELiNK の発火仕様（現行）

- 利用者ごとにボタンをリンクする。リンク時に観測した全スロット（UUID・Major 下位 14 bit・Minor）と、最多受信スロット＝待機スロットを端末ローカルに保存する。未リンク・待機未判定の端末では発信しない。BLE アドレスは判定に使わない。
- **ボタン1/2・短押し/長押しの全 4 パターンで即発信**（パニック時の押し続け・連打を想定、ハッカソンでは誤発信を許容）。条件は「待機以外の状態へ変わった瞬間」または「押下状態のまま `送信時間 + 15 秒`（60 秒設定で 75 秒）以上途切れた後の押下パケット」。
- 二重発信は Android Safety gate の進行中イベント確認と backend の冪等性で防ぐ。通話終了後も押していれば再発信する。
- PendingIntent の `ScanFilter`（`SCAN_MODE_LOW_LATENCY`、保存スロットを bit14/15 無視で一致）で受け、Receiver が直前状態と比較する。`ScanResult.timestampNanos` が 10 秒より古い一致は捨てる。
- `connectedDevice` Foreground Service で常駐し、通知欄に「LIFELiNK 見守り中」を常時表示する（表示が消えたら見守り停止の合図）。60 秒ごとに heartbeat をログへ出す。バッテリー最適化除外を案内する。
- 既定はドライラン（発信しない）。画面のスイッチで OFF にすると実発信する。

## 5. 決定

- 送信時間は **60 秒**（途切れ判定 75 秒）。画面 OFF 中の受信空白（最大約 23〜38 秒）より長く、取りこぼしをほぼ無くせる。代わりに同じボタン・同じ押し方の押し直しは 75 秒空ける必要がある。別ボタン・短押し↔長押しの切替なら 60 秒中でも即発火する。デモで連続して押す場合は別の個体を使う。
- Beacon は画面 ON では約 2 秒、ロック中は数秒〜数十秒の遅延がある予備経路として扱う。押下ごとの確実な配送・回数・ACK が必要な用途は GATT（Seeed XIAO nRF52840、Model XIAO-nRF52840、FCC ID Z4T-XIAONRF52840、技適 211-220207）を本命とする。
- 別チームの PoC（PB-BTN-01、長押し Major の完全一致 filter、観測 10 秒以内・前回受理から 10 秒以上）とも対応関係は一致。ロック中の長時間待機で受信できなかった結果とも整合する。

## 6. 既知の制約と後続タスク

- 画面 OFF 中の受信は OS により間引かれる（充電中の計測。USB 非接続ではさらに悪化する可能性）→ P3-03 で USB 非接続・スキャン再登録の効果を測る。
- APK 更新（`adb install -r`）で見守りサービスは停止する。更新後は「見守りを開始」を押し直す。
- ボタンが IDLE・電池切れ・範囲外でもアプリからは区別できない → P3-04 で待機広告の最終受信時刻による死活表示と警告を実装する。
- 長時間ロック（15 分〜2 時間）・再起動後の復帰・通知権限拒否時の挙動は未検証 → P3-02。
- 計測ログ: 画面の「Beacon ログ」（選択/一括コピー可）と logcat タグ `LIFELiNK.BeaconLog`（判断）、`LIFELiNK.Beacon`（パケットごと）。画面 OFF/ON・ロック解除・充電状態・3 秒以上の受信空白（「受信再開: ◯秒ぶり」）もアプリ内ログに残る。
