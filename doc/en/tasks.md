## P2: Ingesting ambient sound (current data foundation + staged experimentation with carrier conferencing)

**Additional decision on 2026-09-26**: The user confirmed a manual 3-way call via Galaxy + SoftBank and mic reachability after locking.
Next, evaluate a **carrier IMS Conference + Twilio AI phone leg** (not a Twilio Conference) in staged steps as P2-12 through P2-16.
The existing Cloud Run / Firestore / Discord will be shared, the existing SOS will be preserved, and the plan is for Beacon's legacy/experimental route selection to default to legacy.
Details, evidence, and recovery steps are in chapter 0 of [doc/en/ambient-verification.md](doc/en/ambient-verification.md). **This round is documentation only; Twilio participation and automatic control are not yet implemented/verified**.
P2-09 through P2-11 remain on hold as an alternative approach using independent recording, and are not a prerequisite for this phone experiment.

**Policy shift on 2026-09-26 (human decision)**: It was decided that the migration to chapter 8a's `emergencySessions`/`facts`/`timeline`/`delegations` (formerly P2-01 through P2-06)
**will not be implemented for the hackathon**, and it was moved to PX-14 through PX-19. There are 3 reasons:

1. What we actually want to do (ingesting ambient sound) does not require a new collection. If independent recording is adopted for the existing `emergency_events/{id}/updates`,
   an added `type: "ambient"` proposal can be considered. For the carrier conference, the meaning and labeling of the existing transcript will be considered (the contract will be frozen in plan first).
2. The core of the old P2 is a rewrite of `voice.ts`, which is the most fragile part, and there is no reason to destabilize it again right before submission.
3. The frozen schema and rules/indexes are already deployed, and leaving them as-is causes no harm. It's fine that the design exists but the implementation is deferred.

Chapter 8a of [doc/en/plan.md](doc/en/plan.md) **remains as a design document as-is** (not deleted).
